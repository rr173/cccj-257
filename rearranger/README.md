# 固定块数据文件离线原地重排工具

把一个由等长块组成、接近写满的数据文件，按作业描述里的新布局**原地**重排。
不做整文件副本、不需要随文件大小增长的内存；介质上只额外持久化一个块长的
备用载荷和一组纯元数据。任何阶段被杀或断电后，用**同一条命令**重开即可从
断点续接到正确的新布局。

## 作业描述（输入 JSON）

```json
{
  "version": 1,
  "block_size": 4096,
  "layout": [10, 1, 0, 11],
  "old_digests": ["<sha256 十六进制>", "..."],
  "digest_alg": "sha256"
}
```

* `layout[t] = s` 表示**目标槽 t 的字节取自旧槽 s**。
* 必须覆盖全部目标槽（长度等于槽位数），是一个任意函数：旧槽可以没有去处，
  也可以同时给多个目标供数；槽号越界在预检阶段被拒。
* `old_digests[s]` 是**本轮作业开始前**旧槽 s 的 sha256。坐标与摘要都相对
  作业前文件，而不是写到一半的文件。
* 文件大小必须正好是 `槽位数 × block_size`。

## 使用

```bash
# 执行（或续接）同一个作业；元数据默认放在 <data>.rearrange.d/
python3 -I rearrange.py run --data data.bin --job job.json

# 完工后按完成凭据全量核验每个新槽
python3 -I rearrange.py verify --data data.bin --job job.json
```

## 侧车目录里持久化了什么

全部位于 `<data>.rearrange.d/`，除备用块外都是不含可还原载荷的元数据：

| 文件 | 内容 |
| --- | --- |
| `journal.json` | 作业哈希、文件身份、图分解结果、各阶段游标；带自身 sha256 签名，原子替换 |
| `spare.block` | **至多一个块长**的备用载荷，仅在处理多节点环期间存在，完工即删 |
| `credential.json` | 完成凭据：每个新槽的最终摘要、文件身份、作业哈希，带签名 |
| `job.lock` | 独占锁文件（flock，进程退出自动释放） |

载荷缓冲只有“一块”这一级：所有读都以 `block_size` 长度 `pread`，所有写都从
单块缓冲 `pwrite`；没有 mmap、没有整文件 `read()`、没有按文件大小分配的缓冲。

## 算法：函数图分解

把 `f(t)=layout[t]` 看成有限集上的函数，其函数图由若干“环 + 喂入环的树”组成。

1. **树节点（Kahn 剥叶，自底向上）**：对每个不在环上的目标槽 t，其源槽
   `f(t)` 在 t 被处理前一定尚未被覆盖，直接 `t <- 原始(f(t))`。单块直写，
   不需要备用块，重做天然幂等。
2. **环**：设一个环按 `f(c_i)=c_{i+1}`（下标模 L）排列。
   * `spare <- 原始(c0)`，落盘并 fsync；
   * 对 `i = 0..L-2`：`c_i <- 原始(c_{i+1})`——每一步的源槽在该步之前从未
     被写过，因此读到的必然是原始内容；
   * 最后 `c_{L-1} <- spare`（即原始(c0)）。
   自环 `f(c)=c` 无需备用块，目标内容就是自身原始内容。

## 崩溃一致性（在每个提交点前后杀掉都能续）

不变式：**先写数据并 fsync，再原子提交日志；日志游标只在提交成功后前进。**

* 日志用“临时文件 fsync → rename → 目录 fsync”原子替换，带签名防篡改。
* 数据/备用块的每次写都在循环里处理任意短写，写满后立刻 fsync。
* 崩溃后重开：
  * 已提交的槽按目标摘要核对；在飞槽允许是“原始”或“目标”两种一致状态之一
    （撕裂的块两种摘要都对不上，会被当作外部损坏拒绝）；未触槽必须仍是原始摘要；
  * 备用块若处于 `rotate` 阶段，必须等于环起点的原始摘要；`spare` 阶段崩溃留下
    的撕裂备用块直接删除重做。
* 因为重做一步时读取的源内容在该步之前不会被覆盖，所以每一步都是幂等的。

## 首次写盘前的预检（错误时数据盘零改动）

`run` 在打开数据文件写句柄、创建侧车目录之前依次核验：

* `block_size > 0`、布局长度与摘要数量等于槽位数、槽号不越界；
* 文件大小正好是槽位数的整数倍；
* **逐块**读取并核对全部 `old_digests`。

任一失败以退出码 3 退出，不创建作业目录、不写数据盘。

## 续接绑定（外部写入不能冒充正常续接）

续接必须同时满足，否则以退出码 4 拒绝、不写数据：

1. 作业描述规范化哈希与日志中的 `job_hash` 一致——换布局/换摘要即视为另一作业；
2. 文件身份（大小、设备、inode）与日志一致；
3. 日志自身签名有效（日志被改即拒）；
4. 逐槽摘要能与日志游标对应（见上），任何外部写入导致的偏离都会被发现；
5. 备用块摘要与当前环起点绑定。

## 完成凭据与幂等重开

* 全部槽完成后，逐槽按“`old_digests[layout[t]]`”核对，再写 `credential.json`
  （原子替换 + 签名）。
* 同一作业再次 `run`：检测到凭据后只校验凭据与文件身份，**绝不再执行一遍
  布局**；`verify` 子命令按凭据全量核对每个新槽。
* 不要求中止后回退到旧布局（作业未宣布完成期间文件不对普通读者开放）。

## 独占访问

对数据文件描述符和侧车锁文件都加 `flock(LOCK_EX|LOCK_NB)`：同一作业的第二个
进程立即以退出码 6 失败；锁随进程退出自动释放，崩溃不会留下死锁。

## 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 成功（完工，或此前已完工的幂等重开） |
| 2 | 命令行用法错误 |
| 3 | 预检失败（数据盘未被改动） |
| 4 | 续接被拒绝（身份/签名/逐槽摘要不符，疑似外部写入） |
| 5 | 介质 IO 错误（题目约定不要求容忍介质自身损坏） |
| 6 | 文件已被另一进程独占 |
| 9/137 | 测试故障注入主动 `os._exit`（正常运行不会出现） |

## 测试与演示

```bash
python3 -I test_rearrange.py          # 全套：216 个固定故障点 + 40 场随机风暴
./demo_shortwrite_resume.sh           # 小文件短写中断 -> 续接 -> 凭据核验
```

测试夹具覆盖：端到端、预检零写盘、续接绑定（改数据/改日志/换作业/换文件）、
完工不重排、独占锁、备用块大小上限、400 块规模（含 50 节点环）、源码级载荷
缓冲护栏，以及在数据/备用块的 `pwrite`/`fsync` 与日志提交四个边界上的短写和
杀进程组合。

## 明确不覆盖的范围（按题目约定）

* 不容忍介质自身损坏，也不容忍已 fsync 数据的回滚；
* 不提供中止后回退旧布局的能力；
* 摘要算法仅支持 sha256。
