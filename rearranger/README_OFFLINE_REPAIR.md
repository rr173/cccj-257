# 归档包离线修复（行列异或校验，重建与迁移前逐字节相同的归档包）

合并后的固定块归档包迁入冷存储后，原始来源归档就会下线。坏盘上的
`image.bin` 可能出现内容翻转、短块（只剩文件前缀）、缺槽，`manifest.json`
甚至可能整个丢失。本能力在**不依赖任何已下线来源文件**的前提下，仅凭迁移
时封存的修复资料，在另一块盘上重建出与迁移前**逐字节相同**的归档包，而不是
重新合并来源文件。

本能力与原有**多归档合并**（`archive_merge.py`）和**单文件原位重排**
（`rearrange.py`）相互独立：它只读坏盘与校验介质、只写一个此前不存在的输出
目录，不改写原包与修复资料，也不改变合并、核验、原位重排的既有命令行为。

| 文件 | 作用 |
| --- | --- |
| `offline_repair.py` | 修复资料制作（`make-kit`）与离线重建（`repair`）主程序，仅 Python 3 标准库，建议 `python3 -I` |
| `test_offline_repair.py` | 测试夹具：端到端、链/级联恢复、秩亏、矛盾关系、随机擦除对 GF(2) 秩判定、原子发布故障矩阵、独占锁、只读一轮、缓冲护栏 |
| `demo_offline_repair.sh` | 端到端演示：制作资料 → 模拟坏盘 → 离线重建 → 逐字节比对 → 关系不足失败 |

## 角色与两份数据

* **分组表**：JSON 的 `rows`、`columns` 两个有序列表，分别把全部镜像槽号
  划分成互不重叠的非空组；每个槽在每个列表中恰好出现一次，槽号从 0 开始，
  两组列表各自按给定次序编号。空镜像对应两个空列表。
* **两份校验载荷**（分开存放）：每份按本侧组号依次存“每组内整块逐字节异或”
  的结果，一个组占一个块。
* **描述文件** `repair_desc.json`：记录原清单的精确字节、分组、两侧校验块
  与各原物理槽的 SHA-512，并带自身签名。
* **描述文件 SHA-256**：操作员必须保存在**修复介质之外**，修复时用来确认
  描述文件本身没有被改动。

## 操作员需要分别保管哪些文件

迁移时（健康盘上）生成一个修复资料目录，其中三份文件建议分散保管：

| 保管位置 | 文件 | 丢失/损坏的后果 |
| --- | --- | --- |
| 校验介质 A（与坏盘分离） | `repair_rows.bin` 行侧校验载荷 | 丢失的行方程不可用，可恢复性下降 |
| 校验介质 B（与 A、坏盘分离） | `repair_cols.bin` 列侧校验载荷 | 丢失的列方程不可用，可恢复性下降 |
| 任一可信介质 | `repair_desc.json` 描述文件（含原清单字节、分组、全部 SHA-512） | 无描述文件则无法修复 |
| **介质之外**（纸面/密钥库/另一站点） | 描述文件 SHA-256（`--digest-file` 输出或终端打印值） | 无法证明描述文件未被篡改 |

两份校验载荷**不要与待救镜像放在同一故障域**；描述文件的 SHA-256 必须脱离
所有数据介质单独留存，否则坏盘连同描述文件一起被改时无法发现。

## 用法

```bash
# 迁移时：从健康归档包与分组表制作修复资料
python3 -I offline_repair.py make-kit \
    --package healthy.pkg --groups groups.json \
    --out repair-kit --digest-file offmedia.sha256

# 故障后：离线重建到一个尚不存在的输出路径
python3 -I offline_repair.py repair \
    --descriptor repair-kit/repair_desc.json \
    --digest "$(cat offmedia.sha256)" \
    --old-image  /failed-disk/image.bin \
    --rows-parity /media-a/repair_rows.bin \
    --cols-parity /media-b/repair_cols.bin \
    --output /healthy-disk/restored.pkg
```

也可从既有入口转发（命令行参数完全相同）：

```bash
python3 -I archive_merge.py make-repair-kit ...   # 等价 make-kit
python3 -I archive_merge.py repair ...
python3 -I rearrange.py make-repair-kit ...
python3 -I rearrange.py repair ...
```

### 分组表示例

```json
{
  "rows":    [[0, 1], [2, 3], [4, 5]],
  "columns": [[0, 2, 4], [1, 3, 5]]
}
```

两个列表都必须把 `0..slots-1` 划分成互不重叠的非空组；空镜像用
`{"rows": [], "columns": []}`。组越密（组越小），可容忍的坏槽越多；极端情况
下每个槽单独成组（两侧都是单槽组），即使整份镜像丢失也能完整恢复。

## 制作阶段的前置条件（不满足不交付修复资料）

`make-kit` 先对健康归档包做**脱离原合并请求**的自洽核验，全部通过才产出资料：

* 清单自身签名有效、格式/版本正确；
* 镜像文件大小等于 `slots * block_size`，逐槽 SHA-256 与整体 SHA-256 与清单一致；
* 镜像内部无“内容相同却未合并”的重复块；
* 每个来源归档的 `slot_map` 越界检查、映射槽摘要与声明摘要一致、槽位按首次
  出现编号、全部镜像槽都被来源引用。

同时分组表必须合法（两侧都完整覆盖、互不重叠、组非空、槽号不越界）。这个
过程不需要任何已下线的来源文件。

## 修复阶段信任什么、拒绝什么

* **先**校验描述文件：与留存 SHA-256 不符、自身签名失效或结构无效，立即拒绝
  （退出码 3）。**绝不读取或信任坏盘上的清单。**
* 旧镜像的缺失文件、短块、缺槽、与封存 SHA-512 不符的块，一律视为**擦除**。
* 旧镜像或校验载荷**超过封存长度**、或出现其他 I/O 错误，直接拒绝（退出码
  3/5），不猜不补。
* 块的身份始终是**封存时的槽号**：好块只写回它自己的槽偏移，重建块也只按
  槽号落位；即使另一个槽内容摘要相同，也绝不拿来顶替。
* 输入在操作期间不会被其他程序改写。

## 恢复算法：叶剥离（行列二部图上的连锁求解）

把每个镜像槽看成连接“所在行组”和“所在列组”的一条边，每个仍可核验的校验
块是其组顶点上的异或方程（组内成员块异或 = 校验块）。

1. 某个组只剩**一个未知槽**时，该槽 = 校验块 ⊕ 组内其余已知槽，唯一确定；
2. 定出一个槽后，它在另一侧所在组的未知计数也减一，可能又出现新的单未知组，
   于是连锁剥离，能还原跨行列连成一条链的整串坏槽；
3. 剥离结束后若仍有未知槽，说明有效方程秩不足、解不唯一，**明确失败**
   （退出码 8），绝不用 SHA-512 摘要当额外方程去猜内容。

可恢复情形不限于“每组一开始至多坏一个块”：只要坏槽链上仍有足够的完好校验
块形成一棵可剥离的树（有效方程数等于未知槽数），整条链都能还原。测试用
GF(2) 高斯消元的秩判定作为参考，对 60 组随机擦除/校验失效图案逐项核对，
工具的可解性结论与参考实现完全一致。

任何重建块都要立即通过该槽的封存 SHA-512；发布前还要：

* 逐槽复核 SHA-512 与镜像整体 SHA-256；
* 用所有仍可核验的校验块复核组异或关系——能通过求解、但与关系**互相矛盾**
  的校验块会在这里被拦下，不发布。

## 成功结果与失败语义

* 成功输出仍是原读取系统可直接使用的归档包：**原清单字节、镜像尺寸、槽顺序、
  来源映射全部不变**，与迁移前逐字节相同，可直接用 `archive_merge.py verify`
  按原请求核验。
* 镜像先写在输出同级的隐藏临时目录（`.offline_repair.<名字>.tmp.*`），清单
  原子落盘并回读比对后，才用一次目录 rename 发布。中断或失败时最终路径上
  不会出现半个包。
* 输出路径必须**尚不存在**，已存在一律拒绝覆盖（退出码 7）。
* 原包与修复资料全程只读，不会被改写。
* 同一输出加 `flock` 独占锁，第二个进程以退出码 6 立即失败。

## 资源与介质约束

* 故障盘上的旧镜像**只读一轮**：按槽号顺序扫荡，块内允许短读后续读同一块的
  剩余字节，但不会回头重读任何块；好块直接落位到可回读的目标盘。
* 校验介质与未发布的目标数据可以回读。
* 载荷内存不随镜像槽数或分组数增长：任何时刻只保留若干 `block_size` 大小的
  缓冲，不缓存整份镜像或整份校验载荷，也不另存完整临时副本；随规模增长的
  只有摘要、分组成员、未知计数、好/坏标记等非载荷元数据。
* 无 mmap、无整文件 `read()`，所有载荷 IO 都是块长的 `pread`/`pwrite`。

## 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 成功（资料已生成，或归档包已重建发布） |
| 2 | 命令行用法错误 |
| 3 | 描述文件/分组/输入结构核验失败（含留存摘要不符、超长文件），未发布 |
| 4 | 健康归档包自洽核验失败（make-kit 拒绝交付资料） |
| 5 | 介质 IO 错误 |
| 6 | 同一输出已被另一进程独占 |
| 7 | 输出路径已存在，拒绝覆盖 |
| 8 | 修复失败：校验关系不足、互相矛盾或重建字节不符封存校验，不交付部分结果 |
| 9/137 | 测试故障注入主动 `os._exit`（正常运行不会出现） |
